# Assembling the strategy doc

Read this when the three phases are done and the output needs to become a document someone will act on or ratify.

The PSD output is the **engine** of a strategy doc, not the doc itself. The phases produce artifacts; a doc makes a case.

---

## Rumelt-kernel structure

Offer to assemble the three phases into:

1. **Diagnosis** — the situation stated with the unflattering metrics, not the flattering ones
2. **Vision** — where this goes if it works
3. **Priorities and explicit non-priorities** — what we are and are not doing
4. **Evidence** — including willingness-to-pay
5. **Differentiation** — the Phase 3 table
6. **Game plan** — the coherent set of actions
7. **30-day actions** — what happens now

## "What would make this wrong"

Every deliverable carries this section. List the assumptions that, if false, break the analysis — and lead with the single cheapest data pull that gates the most phases (e.g. the end-of-term decision mix). If the client funds only one query, it should be that one.

This is the difference between a deck that survives contact with data and one that gets quietly abandoned.

## Framing for the room

Before the strategy is ratified, offer the same content two ways:

- **Analysis framing** — hypotheses + open questions
- **Strategy framing** — decisions + actions

Same substance, different political weight. Let the user pick based on where the decision actually stands — presenting hypotheses as decisions invites a fight over ratification the work hasn't earned yet, and presenting decisions as hypotheses invites endless re-litigation.
